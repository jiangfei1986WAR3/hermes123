# Trading Candidate Screening

本技能是**深度分析后的历史风险检查清单**，不是扫描器的第二套评分器，也不是独立的最终裁决层。

职责边界：
- `binance-market-scanner` 只负责批量采集、打分、排序和选出最多3个候选；除流动性/数据不足/信号冲突外，不在扫描层叠加本技能的案例禁手。
- 扫描分达标的Top候选先全部运行 `fetch_klines` 和 `trading-analysis`，再使用本技能复核当前结构；禁止因历史案例在深度分析前提前淘汰。
- `trade-execution-planner` 统一负责触发价、结构止损、TP、R、数量、风险额与最终 `PLAN_READY/WATCH_ONLY/NOT_EXECUTABLE` 状态。
- 本技能中的历史模式只能提示复核，不能仅凭“像某个旧案例”否决；最终结论必须由本轮原始K线、有效结构、真实R、量价和市场环境支撑。

选完候选、跑完 trading-analysis 后，对每个进入执行层的候选复核历史风险模式，并把当前事实交给 `trade-execution-planner` 数值化。只有 planner 能给出最终状态；本技能输出“命中/未命中哪些复核项及证据”，不能自行标 `PLAN_READY/WATCH_ONLY/NOT_EXECUTABLE`。

## 风险检查模式（用于复核，不在扫描前机械淘汰）

1. **破位空但已超卖**：4h RSI < 30（超卖）且现价距前低 < 1 ATR → 追空位置差。
   - 复查条件：等反抽到跌破位/短均线阻力（如 1h MA7）再评估
   - 例：AAVE 2026-08-06，S78 全场最高分，4h RSI 29.4 + 距前低 0.5% → 不建
2. **回踩多但止损距离过大**：止损须 ≥ 1 ATR（低价高波动币 15m ATR 常 ≥ 3%），若 TP1（最近结构位）收益 < 1.2R → 计划 R 不达标。
   - 复查条件：等价格实际跌到回踩区企稳后，用更近止损（回踩低点下方）重估
   - 例：COTI 2026-08-06，L52 4h/1d 多头排列，15m ATR 3.4% 导致回踩止损 5.3%、TP1 仅 0.65R → 不建
   - **镜像陷阱（R达标但止损无缓冲）**：为把 TP1 R 凑到 ≥1.2R 而把止损压到回踩低点上方无 ATR 缓冲处 = 一样不建——R 与止损缓冲互斥时两边都不合格。例：ZRO 2026-08-27，L60，保 R 须把止损压到距回踩低仅 0.09%，留正常 ATR 缓冲则 R <1.2 → 不建。**空头侧同理**：TAC 2026-08-29，S60，破位空 R 1.22 压线但止损缓冲仅 0.94×1h ATR（<1）→ 不建；换有缓冲的止损（1.61×ATR）则 R 崩到 0.72 → 双不合格。**反抽空路径独立复核（2.21R 达标）**——先被误标 WATCH_ONLY，用户质询"为什么不直接建反抽空"后按 FIL 08-28 同型先例补建（触发 0.002285/止损 0.002404/TP1 0.002022，dry-run 静默+Cron 正常；次日用户主动要求删除，非规则问题）。教训：**反抽空达标就建，"等反抽"不是 WATCH_ONLY 理由**
3. **追高/追空镜像复核**：高分+24h涨幅过大+1h/4h RSI双超买+巨量分歧，或跌幅过大+15m/1h RSI双超卖+巨量阴线+费率转负 → 标记位置风险，交给 planner 结合结构和R裁决。
   - 24h涨幅 +30%以上的高分多、跌幅 -25%以下的高分空仍须进入Top候选深度分析；不得在扫描阶段仅凭涨跌幅直接跳过
4. **破位空但短线超卖贴下轨**：15m/1h RSI < 35 且现价贴/破 1h 布林下轨、破位低点刚形成（近1-2根K线砸出）→ 追在地板上。
   - 与模式1区分：4h RSI 可能未到30（如42），模式1漏判；此条看**短线**RSI+布林位置
   - 复查条件：等反抽到阻力簇（15m阻力/1h前支撑转阻力）受阻再评估，不直接破位空
   - 例：HYPE 2026-08-09，S70，4h RSI 42 但 15m RSI 33 + 贴1h布林下轨 + 24h低刚砸出 → 建了破位空，用户拿另一模型交叉验证后删除
   - 量化"贴前低"：现价距前低 < 0.3 ATR = 贴脸无缓冲（追空），≥ 0.5 ATR = 有缓冲可建。对照：AAVE 08-14（4h RSI 36、15m RSI 28.8、距前低 0.2 ATR）→ WATCH_ONLY；UNI 08-14（15m RSI 47 中性、距前低 0.63 ATR）→ 正常建破位空且当天盈利
   - ⚠️ **模式1/4（追地板）只否决破位路径，不否决反抽路径**：追地板=现价直接空；反抽空等价格先反抽到阻力带受阻再跌回，入场时价格已离开地板——破位路径被禁手杀死时反抽路径照常独立数值化（R 达标+止损 ATR 缓冲+阻力带真实即建，"等反抽"不是 WATCH_ONLY 理由，见模式2 TAC 08-29 例）
5. **刚平仓币再入场**：该币 24h 内刚止盈/止损（查 trading-history 或 userTrades）且现价在我方出场价上方 → 追高接回自己刚卖的币，排除。
   - 复查条件：价格回踩至出场区域下方企稳，按新的回踩结构重估
   - 例：WLD 2026-08-10，14:33 TP2 0.3429 止盈离场，15:23 扫描仍 L70、现价 0.3481 高于出场价 → 排除
6. **破位空 R 结构压缩**（判定动作：先算 R 再出口——止损=反弹高点/1h 结构上方，TP1=下方最近强支撑，TP1 落支撑上/下方或机械位 → 不建）。三种形态：
   - ①破位已走完大半+现价反弹回破位区上方，RSI 可以不超卖（XRP 例：15m RSI 46），杀死计划的是 R 结构压缩，不是超卖。例：XRP 2026-08-10，S78，破位低点 1.0228 已破且反弹至 1.0296，止损 1.0305 后 TP1(1.2R)=1.0118 正砸日线强支撑 1.012 → 不建
   - ②触发位到第一支撑太近：TP1 对齐第一支撑 < 1.2R，止损怎么收都救不回来或被迫贴阻力（易扫/假破）。例：SUI 2026-08-16，S78，1h 低 0.6742 → 4h 前低 0.6713 仅 0.5%，止损 1h 结构上方 1% → 0.5R；DOGE 同轮 S68，触发 0.06947 → 4h 低 0.06879 仅 1.1%，止损须收贴阻力 0.06999 才够 1.2R，假破风险高 → 均不建
   - ③破位后下方真空：前低本身就是日线区间低，下方无任何支撑参考，TP1 只能机械 1.2R（违 ZEC 禁手）。例：UNI 2026-08-16，S68，4h 前低 3.162=日线区间低，破位后下方真空 → 不建
   - 多头镜像：突破位=可见区间高点且上方无结构时，先拉日线长历史（`api_get('/fapi/v1/klines', {'symbol':S,'interval':'1d','limit':200})`）验证上方阻力簇真实存在，再算 R；TP1 R<1.2 → 不建。例：WLD 2026-08-17，L78 突破多，200日历史确认上方 0.379-0.403 阻力簇，结构止损算出 TP1 仅 1.03R → WATCH_ONLY（复查：回踩 0.350-0.355 缩量企稳后用近止损重估）
   - **TP1 对齐哪一档：强阻力优先，弱档不算目标**。簇输出多档并存时（第一强阻力 + 更近的历史弱档），机械选最近档常算出 R<1.2 而误杀好结构；TP1 应对齐**第一强阻力**（近期刚到过/成交密集的档），更近的弱档只在它进入止损距离量级时才阻断。正例：UNI 2026-08-27，L62，触发 4.547 上方 27天前 4.575/197天前 4.59 两个弱档 + 4天前刚到过的强阻力 4.758（+4.6%）→ TP1 对齐 4.758 得 1.44R 达标，正常部署并监控。反例：FARTCOIN 同日，触发 0.2187 上方 3% 内 8 档全是密集簇（无"弱档"可言）→ 0.82R 不建。判别关键：看弱档与强阻力之间是否隔着止损距离量级的真空——有 = 强阻力当 TP1；无 = 整片簇都是天花板
   - **双层簇（近端簇 + 远端簇叠压）= 整片天花板**：昨簇/近簇之上若再叠一层历史老簇（两层间距同为止损距离量级、中间无真空），TP1 对齐远端簇照样被近端簇压死——须用 `resistance_above.py --ref=<簇顶上方>` 逐层探到真空为止，任一层出现在 TP1 量级即否决。例：TRUMP 2026-08-29，触发 2.892-2.936 八档近簇之上 0.14% 又是 2.962-3.01 五个月老簇（ref=2.94 复查才发现）→ 突破/回踩 TP1 双压死 ≤0.6R。**复查条件必须绑定主否决因**：否决主因是簇时，"站回 MA25/企稳"这类次级条件自动满足 ≠ 主因解除——复查条件必须写成"放量站稳簇顶上方"，否则下轮复查会白跑（TRUMP 08-29 上午草案教训）
   - ⚠️ **禁止用 fetch_klines 输出的 `阻力位/支撑位` 字段算 TP1 R**：那些位取自本次拉取窗口（100 根）的近期高低点，会漏掉窗口外的历史密集簇，算出的 R 可能高一个数量级。突破/破位类候选一律先跑 `resistance_above.py` / `support_below.py` 拿 200 日簇，再算 R。同类误算 2026-08-27 MAGMA 已是第二次（前次见 `references/intraday-resistance-vs-daily-cluster-2026-08-25.md`，本次数字见 `references/incident-log.md`）：按 fetch_klines 的日线阻力算出 2.96R 一度看似达标，200 日簇显示触发价上方 0.16% 就是第一档 → 实为 ≈0.04R。
   - **空头侧同样必须验证**：破位类计划先跑 `scripts/support_below.py SYMBOL --ref=SYMBOL=触发价`（`--ref` 传触发价，不是破位位）枚举 200 日日线低点簇，再按真实 R 裁决。`PROPOSED / NOT ACTIVE`：「参考位下方 <1% 内 ≥2 档 = 贴脸支撑簇」这条快捷判据未经用户批准，只作复核提示，不得替代 R 计算——同一支撑簇在不同止损距离下 R 可从 0.16R 到 1.2R+。案例见 `references/incident-log.md`。
   - 复查条件：放量跌破该支撑并站稳其下（空间打开）再评估；或反弹至阻力簇明显受阻另议
  - **R 误算自纠流程（2026-08-29 NIL 例）**：选币阶段的手推 R 只是草稿，**写 plan 前必须用 Python 以最终选定参数复算**（`R = (TP−触发)/(触发−止损)` 一行代码），不得沿用草稿数字——NIL 当轮草稿手算"TP1 1.24R 达标"，终检复算 TP1 0.53R / TP2 1.10R（错在止损距离取值），当场撤回改判 WATCH_ONLY，plan 尚未落盘所以零成本。正面意义：把"手算→写文件"之间插一道机器复算闸，误算在落盘前暴露
7. **反弹多但个币自身日线空头排列**：日线 MA7<MA25 + 日线 RSI 偏弱（<45）+ 超跌反弹后横盘缩量滞涨 → 即使回踩 R 达标（≥1.2R）也不建。与退潮期大盘纪律区分：大盘弱但个币日线多头排列的强势龙头可建（LINK 08-15 例，日线刚转多头排列 → 回踩计划正常建）；个币自己日线都空头排列的反弹是"弱中弱"，不建。
   - 复查条件：日线收盘站上 MA25（转势确认）后回踩企稳再评估；或放量突破反弹高点站稳另议
   - 例：NEAR 2026-08-15，L58，回踩多 R=2.7R 达标，但日线 MA7<MA25、RSI 40.5、1.536→1.669 反弹后横盘 3 天缩量滞涨 → WATCH_ONLY
   - **判据须三要素齐备才判**：只有日线 MA7<MA25 但反弹**刚放量启动**（4h 大阳、非横盘缩量滞涨段）不算——AAVE 2026-08-18 例：日线 MA7<MA25、RSI 46.3（≥45 边缘）、4h 放量 2.51x 大阳刚启动 86.3→88.4 → 回踩多正常建（TP1 3.0R）。区分关键词：滞涨段（反弹走完横盘缩量）vs 启动段（放量大阳、动能新起）
8. **破位空但费率极端负（空头拥挤）**：funding < -0.003 级别 = 空头过度拥挤，轧空反抽风险高 → 不建。
   - 例：HOME 2026-08-16，S62，费率 -0.0051 → 不建
9. **崩盘反弹中的高波动币**：4h 区间振幅 >100%（近期崩盘后反弹途中），破位空假破风险极高 → 不建。
   - 例：TUT 2026-08-16，S60，4h 振幅 165%（0.0757→0.0285→0.0309 反弹中）→ 不建
10. **大盘 15m 放量下压时的多头风险复核**：BTC/ETH 日线空头排列且 15m 量比>1.5、主动买盘<0.48（放量下跌）时，多头候选大概率被 market_filter 拦；仍完成Top候选深度分析，并把环境冲突交给 planner 和计划内 market_filter 处理。
   - 例：2026-08-16 扫描，HYPE L74/LINK L64/WLD L64 三个多头候选全灭于环境关（逆势+filter 会拦）
   - **对称场景（大盘 15m 放量上攻→空头降级）**：BTC/ETH 量比>1.5 且买盘>0.52 时，空头候选整体降级（filter 拦空），多头放行；已有空头计划即使触发也会被 filter 挡——如实告知用户"触发会被拦"而非报故障。例：2026-08-18 BTC L68 1h 量比 3.19 放量突破 → AAVE/LINK 回踩多正常建，AVAX 已有破位空计划提示触发也会被拦
11. **突破计划风险额复核**：现价接近触发位只提示复核，**不是独立禁手**。从触发价计算：`qty=(10×杠杆)/触发价`，`风险额=qty×|触发价−结构止损|`。风险额必须展示并参与候选比较，但当前没有用户批准的固定USDT自动否决阈值；不得单凭2.6U判 `WATCH_ONLY`。
   - ⚠️ **统一计算口径**：R 和风险额一律从 `entry_trigger` 算，禁止用现价。止损优先取触发位下方最近且有效的回踩低点（可来自15m或1h），同时须容纳正常 ATR 波动；禁止机械固定为15m前低，也不能无依据扩大到更远阶段低点。**风险额禁止口算**——`qty×|触发价−止损|` 用 Python 算完再进表格（2026-08-27 UNI 汇总表口算写成 0.84U，实为 22×0.0843=1.85U，漏乘名义价值口径）。
   - 复查条件：放量突破站稳后，以突破位下方结构止损重算；或等待回踩企稳后，以新回踩低点重估。案例见 `references/incident-log.md`。
12. **放量突破但短线双超买+巨量已顶到区间最高点**：突破本身是好结构，但若突破瞬间 15m/1h RSI 双超买（>70）+ 15m 量比 >5 巨量 + 现价已顶到 4h 区间最高点（距高点 <0.2%）→ 追在突破最高点，回踩风险大。
   - 与模式3区分：24h涨幅可能不大（<15%），杀死计划的是**短线**RSI+巨量+顶格位置，不是 24h 涨幅
   - 复查条件：等回踩突破位缩量企稳、RSI 从超买回落 → 再评估回踩多
   - 案例见 `references/incident-log.md`。
13. **结构止损超出强平距离（物理不可执行）**：固定保证金杠杆下 10x 强平距开仓价约 -10%（BTC 20x 约 -5%，叠加维持保证金实际更近）。结构止损（24h低/回踩低下方带 ATR 缓冲）距触发价超过强平距离时，止损单永远排在强平之后触发 = 计划物理不可执行，与 R 无关。
   - 与模式2区分：模式2是"止损太远导致 R 不达标"（可等回踩企稳用更近止损重估）；模式13是"止损必须那么远且已越过爆仓线"（根本无法挂出），无等价格的复查变体；低价高波动币（15m/4h ATR 百分比大）最易命中
   - 复核方法：止损距离% 逼近强平距离%（10x≈10%）→ 高危，立即数值验证（exchangeInfo 拿精度，比较止损距离 vs 强平距离）
   - 例：AKE 2026-08-29，L62，15m ATR 3.9%（约4.2%），24h低结构止损距触发 -12.5% > 10x 强平距离 -10% → NOT_EXECUTABLE（非 WATCH_ONLY）

## 禁手先例要复核（不按币种记忆排除）

禁手规则判的是**指标状态**，不是币种名。曾被某禁手模式拒绝的币，后续扫描再现时必须重算该模式当时命中的指标现值；条件不再成立 → 正常建。
- 例：PAXG 曾按追高禁手被拒（24h涨幅小但 4h RSI≥80 + 日线上轨外）；08-10 再现时 4h RSI 67.6、日线布林中轨上方 → 禁手条件不成立，正常建计划并监控

## 输出纪律

- 本技能只输出复核证据，不输出最终状态；最终 `WATCH_ONLY` 候选由 planner 在汇总里给出复查条件
- 对扫描分≥60且进入最终比较的候选，必须把当前复核证据交给 planner，并要求其给出**数值化计划草案**（触发价、结构止损、最近结构TP、风险额与R）；不能只报RSI/涨跌幅等标签。比较“是否优于现有计划”时统一用触发价口径，禁止拿现价R对现有触发计划R。
- 若 planner 结论是“结构勉强合格但不优于现有计划”，必须明确它为何不构成新增计划，并保留现有计划不自动替换。
- **持仓中找更好机会的判定基准**：用户已持仓却发起扫描时（“有没有更好的”），比较基准 = 已持仓币的分数/结构，不是“从零选最优”。若已持仓币本身就是全场最高分，如实回答“你手上已是最好的，本轮无更优候选”，不硬凑新计划。与“候选<60 无达标”区分：此时候选可能 ≥60 但全命中禁手，且被比较对象是已持仓头寸（08-26 晚 FARTCOIN 长76 例）。
- 用户常拿另一对话框的模型结论来交叉验证（2026-08-09 曾据此删掉 HYPE 破位空）。收到时逐候选对照双方结论，分歧处说明各自依据，把最终取舍交给用户（保持/改观察哨兵/删除），不硬辩
- **高分候选不得初筛跳过**。Top候选先完成深度分析；若最终未建计划，planner必须给出R/结构数据，不能用“相关性低”“波动小”等印象词代替证据
- **Top3 全灭 ≠ 本轮结束**：Top3 被数值否决后，扫描分 ≥60 的其余候选（尤其零警告、结构成熟度高的回踩型）必须补跑 fetch_klines + 分析 + 数值草案，再由 planner 宣布“本轮无达标候选”。默认只取3个是排序上限，不是收工理由；用户说“仔细点/别偷懒”时更要补查，并在汇总里列出补查了哪几个、各自触发/止损/风险额/TP1 R。案例见 `references/incident-log.md`。

## 历史计划回放与归因

- 回放旧交易时先区分：①当时**没有某项已确认门槛**；②当时**使用了错误计算口径**；③按当前已确认规则仍会放行。不能仅凭旧账本的结果反推当时用了现价计算。
- 使用现有规则重判，必须从账本恢复 `entry_trigger`、原始止损、TP、数量，再统一计算 `风险额=qty×|entry_trigger−stop|` 与 `TP1 R`；计划已被滑点校准时先还原平移值。缺数量只能判断 R，不能声称风险额已核实。
- 2.6U是历史上Agent形成的筛选建议，未经用户批准，当前不用于重判“今天不会建”；历史回放只展示风险额及严重程度，并交给 planner 按当前已确认规则判断。
- 只有存在当时分析草稿/会话证据，才能认定“误用现价”；否则准确表述为“按今天标准会被拦”，不要扩大归因。详见 `references/historical-plan-replay.md`。

## 与流程的衔接

- 前置：binance-market-scanner 扫描 → trading-analysis（fetch_klines 深度分析）
  - 读扫描 JSON 前先看 `references/scan-json-structure.md`：results/topLong/topShort 都是嵌套结构（`r['long']['score']`），只有 summaryRows 是扁平键（`longScore`/`m15Close`…）；对嵌套数组用扁平键 .get() 会静默全返回 None 不报错（08-17 例：排名排序全靠 None，白跑一轮），混用会 KeyError 或静默错排
  - ⚠️ **K线拉取 400 但 exchangeInfo 仍 TRADING = 疑似下架前数据通道异常**：fetch_klines/api_get klines 与 ticker 全 400 时先换 api_get 重试一次，仍失败 → 无法分析 = NOT_EXECUTABLE，禁止凭扫描器快照硬建计划（08-28 TUTU 例：23:10 扫描器能拉全数据，23:11 起 klines/ticker 全 400、exchangeInfo 仍 TRADING；本轮 78 分空头榜首直接出局）。若日后数据恢复，按新数据重走完整分析
- 后置：复核结果 → trade-execution-planner 统一裁决并生成 plan → 验证拦截 → 建监控 Cron
- 本技能是 trading-analysis 与 trade-execution-planner 之间的检查清单，不是入口闸门或最终裁决层

## 市场状态方向纪律（退潮期）

BTC/ETH 4h/1d 空头排列（退潮期）时，逆势多单即使全周期多头排列也易跌破失效线零成本出局（08-14：BNB/XMR 两单同日连续失效，UNI/LTC 顺势空全盈利）。但"弱市禁多"回测被否（被拦组 +8.45U），故不硬禁逆势多：① 靠 market_filter 兜底（BTC 转强才放行）；② 明确预期"可能失效"，不重仓押单边。

**强势币集体超买 + 空头全线退潮 = 高潮/超买风险模式**：可复核信号包括①多头榜高位/超买候选集中；②空头最高分偏低且多为 NEUTRAL/WATCH；③扫描 JSON `stability.jaccard` < 0.5，提示相邻两轮候选名单大幅变化。Jaccard只反映名单稳定性，可能来自高潮、方向切换、闪崩修复或流动性变化，不能单独证明高潮或决定空仓。本技能只把这些事实交给 `trade-execution-planner`；是否“本轮无达标候选”必须由planner在Top候选全部完成深度分析后统一裁决。验证案例见 `references/incident-log.md`。

## 文档维护纪律

- Self-improvement 补丁只应把**稳定、可复用的筛选规则或检查项**留在主文档；单币数字、当轮行情、纠错经过统一压缩为一行式写入 `references/incident-log.md`，避免案例重新淹没规则。
- 自动补丁后立即检查：①是否把提示误写成硬门槛；②计算口径是否与真实触发成交链一致；③案例是否应移入 reference；④是否仅改本技能、未触碰执行代码或其他技能。必要时小范围瘦身，不扩大改动面。
- 新固定阈值或自动否决规则必须标 `PROPOSED / NOT ACTIVE`；未经用户明确批准，不得写成当前生效规则。
