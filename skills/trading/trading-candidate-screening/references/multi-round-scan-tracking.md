# 同日多轮扫描的候选递进跟踪

用户常一天 3-4 轮"找机会"。每轮独立完整跑流程（启动检查→深扫→fetch_klines→trading-analysis→判定），不可凭上轮结论跳过，但必须携带上轮状态：

1. **上轮 WATCH_ONLY 复查条件逐条复核**：满足 → 升级完整分析；不满足 → 继续 WATCH 并给新条件。
   - 08-18 LINK 递进实例：19:05"回踩 9.36-9.40 企稳再评估" → 22:09 回踩完成但回踩类 dry-run 触发被拦（15m 低点已落入回踩区且现价已收复 reclaim）→ 23:12 站回 1h MA7 但最佳回踩位已过、追入 R 差（第一阻力 9.553/9.568 距触发 < 止损距，ZEC 例）→ 不建
2. **上轮拦截候选重新拉数据判定**：价格已变，禁凭"上轮拦过"直接跳过。VVV/GPS 连续 3 轮被追高规则拦，每轮仍重读新数据核对 RSI/涨幅后再出口。
3. **判定可跨轮翻转**：08-18 ZEC 22:09 判"做空与 4h/日线多头矛盾"不建 → 23:12 回踩 4h 布林中轨企稳、转为回踩做多候选（WATCH_ONLY：站上 1h MA25 再评估）。方向、结构随数据更新，不迷信上轮结论。
4. **已持仓/已有计划币每轮核对后排除**：持仓币大涨照排除，但顺带报告 TP1 距离（08-18 SOL 持仓中 L=78 大涨，报告"距 TP1 0.6%"提醒用户）。
5. 用户说"仔细点别偷懒" = 要求每轮完整流程 + 完整分析输出（结论/事实/框架解读/关键位置/操作场景/风险提醒），不是要求更快更短。
6. 多轮之间的行情位移是正常现象：同一币两轮判定不同 = 数据变了重算的结果，不是不一致；向用户讲清"22:09 数据 vs 23:12 数据"的差别。
