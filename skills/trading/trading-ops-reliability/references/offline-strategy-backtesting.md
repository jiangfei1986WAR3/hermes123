# 实盘交易策略离线回测规范

用于评估“若历史交易采用另一种止损、仓位或止盈管理方式会怎样”。回测必须与实盘执行链物理隔离，并按交易所真实机制重建路径。

## 1. 隔离边界

- 单独工作目录，禁止写入 `~/.hermes/`。
- 禁止调用 `execute`、`watch`、`manage`、`process-events`、下单、撤单或交易监控脚本。
- 账户数据只允许签名 GET；市场数据只允许公开 GET。
- 回测开始与结束记录执行器、配置文件的 SHA256 和 mtime，证明零修改。
- 回测建议必须标 `PROPOSED / NOT ACTIVE`，除非用户另行批准上线。

## 2. API 批量提取纪律

历史数据提取会与实盘监控共享同一服务器 IP，必须把限流当成生产安全问题：

1. 先建立本地账本 manifest，只查询必要币种和窄时间窗；不要“币种 × 全日期”暴力循环。
2. 每次 REST 请求显式节流；读取响应头中的权重与 `Retry-After`。
3. 首个 429 立即停止整批，不得逐条继续失败；418 同样立即停止。
4. 等待服务端给出的解封时间后只发一次 `/ping` 探测，禁止倒计时期间反复探测。
5. 行情结果和成交结果落到隔离目录缓存；重跑先读缓存。
6. 不要把大批历史查询安排在监控可能触发的敏感窗口；API临时封禁期间，交易所托管SL/TP仍有效，但Hermes新开仓和管理查询会受影响。

## 3. 数据真值与样本准入

优先级：

1. `GET /fapi/v1/userTrades`：真实成交时间、数量、价格、`realizedPnl`、commission。
2. `income`：REALIZED_PNL、COMMISSION、FUNDING_FEE总账核对。
3. 本地交易账本：原计划、开仓orderId、计划参数；不能单独证明真实成交。
4. 执行日志：定位TP1、保本改单和watch时间；日志估算盈亏不是财务真值。

每笔以开仓 orderId、symbol、方向、时间共同配对；同币多次交易不得只靠symbol聚合。缺实际成交、数量、原SL/TP或生命周期无法闭合的记录排除或单列。保护单创建异常、紧急平仓、部分成交、幻影单、未了结单均分层报告，禁止混进标准完成样本。

## 4. 两套保护价必须分离

账本字段的语义先用 `execution.steps[stop_loss/take_profits]`、挂单日志或历史订单证据确认，不能仅凭字段名猜。执行器若已把成交偏差平移写回plan，则必须同时保存两套价：

```text
delta = actual_entry - trigger          # 有符号，多空同式
actual_SL/TP = stored_SL/TP              # CURRENT真实提交到交易所的保护价
structural_SL/TP = stored_SL/TP - delta  # 反事实D1使用的原结构价
```

- CURRENT不模拟，用同一ledger的真实`userTrades`作为真值；若要重放路径，只能使用`actual_SL/TP`。
- D1数量公式和路径只能使用`structural_SL/TP`。
- 禁止用一个含义模糊的`sl0/tps0`同时代表两套价格；这会制造大量假UNSETTLED或错误止盈止损。
- 数量优先读取真实入场fills；本地回退取`execution.steps[calc_params].quantity`，不要靠两个TP数量相加反推。

## 5. 路径模拟机制

- SL/TP若为 `workingType=MARK_PRICE`：用 `markPriceKlines` 判断触发，不得用last-price OHLC代替。
- 触发不等于成交：触发后的PnL优先用真实fill；反事实路径用普通成交K线估计成交范围，并明确滑点假设。
- 同一分钟同时触发互斥事件时，输出悲观/乐观边界；主报告采用悲观边界，禁止取平均伪装成“最可能”。
- TP1后保本不是瞬时：优先使用日志中的真实改单生效时间；缺失时至少做0/2/3分钟延迟敏感性。
- 入场、减仓、TP、SL都计手续费；funding可得则计入，缺失必须声明。
- 数量按交易所stepSize向下取整，并验证minQty/minNotional。理论数量不可执行时标 `NOT_EXECUTABLE`。
- 截止时仍持仓的交易单列未实现结果，不计入已实现胜率。

## 6. 反事实仓位规则

若方案仅为防守性缩仓：有利或零滑点不得放大仓位。

```text
qty_new = min(qty_original, qty_formula)
```

如果真实实现需要“先按原数量开仓、成交后再减到目标数量”，回测必须另计这次减仓的手续费、滑点和保护单尚未建立的短暂风险窗口；不能把理论上从一开始就是小仓当成零成本实现。

## 7. 最低输出

同时报告：

- 账本总数、真实成交数、完整样本、部分样本、排除数与逐类原因；
- 现状真实PnL与各反事实策略：总净PnL、平均数、中位数、胜率、盈亏比、最大单笔亏损、最大回撤；
- 盈利单少赚、亏损单改善、TP1触发率、未了结数、歧义路径数；
- 逐笔贡献与“剔除最大贡献单”敏感性；
- 悲观/乐观边界以及0/2/3分钟保本延迟矩阵；
- 手续费、funding、成交滑点、数据分辨率限制。

## 8. 完成门

只有在以下全部满足时才能给最终结论：

- CURRENT与反事实使用完全相同的ledger ID集合；CURRENT必须逐ledger直接汇总manifest fills，禁止用大型虚拟`UNMATCHED_RECONCILIATION`补平后声称逐笔归因完成；
- CURRENT汇总与`userTrades.realizedPnl - commission (+ funding)`逐笔及总账对得上；
- 现实已平仓但反事实到现实生命周期末端仍未触发退出时，必须按截止前最后可用价MTM并标`VALUED_AT_LIFECYCLE_END`，不得按0、不得混称已实现；
- 无同币串单；
- `actual_SL/TP`与`structural_SL/TP`分离且抽样能复现关键历史案例方向；
- MARK触发与last成交分离；
- 保本延迟、手续费、stepSize/minNotional已处理；
- 边界/延迟矩阵若完全相同，须逐笔证明样本确无歧义/窗口差异，不能仅因测试代码可运行就判通过；
- 独立复算通过，发布产物本身也无虚拟调节项；旧结果文件必须明确作废，禁止混用不同版本数字；
- 实盘关键文件哈希和mtime与回测前一致。

## 9. 结果沟通纪律

- 首次运行出现大量UNSETTLED、所有边界/延迟完全相同或汇总依赖大额调节项时，先判结果无效并查字段语义/时间边界，禁止急着报收益。
- 不要反复承诺“再等10分钟”；只报告当前完成门、阻断项和已验证证据。异步任务尚未结束时明确说“后台仍在运行”，不要让用户误以为停住。
- 最终报告必须区分：真实CURRENT、反事实SETTLED、生命周期截止MTM、诊断产物、正式发布产物；精确数字发生版本变化时说明原因并只保留最终同版本表。
