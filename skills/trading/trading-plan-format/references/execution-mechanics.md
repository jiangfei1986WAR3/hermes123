# 触发 → 开仓的完整机制（2026-08-07 用户问答沉淀）

用户连续追问"收盘站稳 0.1948 是什么意思""收盘涨到 0.1990 算吗""收盘在 TP1 附近呢"，以下为机制全解，未来会话被问到时直接按此解释。

## require_close=true 的语义

- 用**最新一根已收盘K线**的收盘价 vs 触发价比较（如 15m 触发 → 每 15 分钟确认一次）
- 盘中瞬时价不算（插一下 0.1950 不算，收在 0.1950 才算）

## executor 入场偏差门（校验6，binance_executor.py 约 441-454 行）

- 规则：`现价偏离触发价 > 止损距离 → 拒绝开仓`
- 目的：防暴涨式突破后追高（滑点大、止损距离不合理、R 崩塌）
- 例：触发 0.1948 / 止损 0.1911（止损距离 0.0037）；现价 0.1990 → 偏离 0.0042 > 0.0037 → 拒绝

## 突破质量三档

| 15m 收盘位置 | 系统行为 | 结果 |
|---|---|---|
| 贴触发价（偏离 < 止损距离） | 开仓 | R 结构完好（理想） |
| TP1 附近（偏离 < 止损距离但吃掉盈利空间） | **会开仓但 R 缩水** | 如 TP1 从 1R→0.43R，TP2 1.27R（已知盲区，偏差门不拦） |
| 远超（偏离 > 止损距离） | 偏差门拒绝 | 放弃，不追 |

关键结论：**触发 ≠ 好入场**。理想触发是"贴着触发价的突破"；TP1 附近的触发是盲区（系统会开，但收益结构被破坏）；远超触发被拦。若未来想拦 TP1 附近档，需改偏差门阈值（偏离 > 0.5×止损距离即放弃）——用户暂缓，未实施。

## 失效线实时触发（require_close=false）的插针误杀案例

- ADA 2026-08-06：20:46 建突破多单（触发 0.1948 / 失效 0.1910 实时）→ 20:56:45 瞬时下探跌破 0.1910（插针，20:58 已回 0.1915）→ 计划作废 → 22:15 15m 收盘突破 0.1948，若无误杀将开仓，TP1/TP2 全触发，理论收益 ≈ +2.8U
- 用户知情后**明确确认保持保守**（失效线继续实时触发，宁可错杀），勿主动改
- 复盘纪律：单次错过 ≠ 规则错误（结果偏差/hindsight bias）；规则评估看长期"真破位拦截 vs 插针误杀"比例，不看单次结果

## 生成计划前必算 R（pitfall，2026-08-07 教训）

口头建议/计划草案也必须先验 R：**TP1 收益 ≥ 1.2R 才合格**（execution-rules 已有此条，但"随口建议"环节容易漏算）。8-06 晚 ADA 草案（触发 0.1950 / 止损 0.1911 / TP1 0.1964 / TP2 0.1995）：TP1 仅 0.36R、TP2 仅 1.15R——不合格，用户没建后自行发现并坦白。规则：**报出任何触发价/止损/TP 组合前，先算 R**（(TP-entry)/(entry-stop)），不足 1.2R 就重新设计（收近止损或上移目标），不要拿半成品计划给用户。
