# 普涨行情系统保守的应对框架 + 高波动币风险额超限（2026-08-22）

## 用户问"普涨为什么系统反而保守/是不是系统坏了"（同日两窗口都问过，用户自答"多虑了"）

普涨≠机会，保守=规则工作，不是故障。回答框架：
1. **健康证据**：本轮扫描 0 错误 + 核心 Cron ok + 近期真实链路记录（建过 plan/dry-run/失效拦截/平仓落袋）——不是空口说"没坏"
2. **解释逻辑**：文档定义高潮期=减仓不追后排；系统入场模式都要"位置"（突破要没涨过前高/回踩要缩量不破），普涨把价格推到天上=位置全无；追高禁手/R门槛/风险额上限逐币否决，每个否决有具体理由可查
3. **跨窗口结论一致**=互相印证是行情问题，不是系统问题
4. **比喻（用户接受）**：网没坏，是海里全是小鱼；该建的时候系统不犹豫（当晚 WLFI 达标即建）

当日实证：十轮扫描只建过 WLFI 一个 plan（20 分钟失效零损失），其余全 WATCH_ONLY；空仓躲过 13:00 全市场闪崩（山寨 -16~-23%）。

## 风险额超限第二场景：高波动币（BEAT 08-22 例）

已有"止损距离远→风险额>2.6U"（LIT 例）。第二场景：**币自身波动太大（15m ATR≥4-5%，崩盘/闪崩类）**，即使反抽空结构成立，合规止损（≥1×该周期 ATR，放反抽高点上方）算出的风险额仍远超 2.6U：
- BEAT：反抽 0.1865 受阻回落结构成立，但 15m ATR 5%，止损必放 0.1865 上方 → 距离 9%+ → 风险额 2 倍超限
- 处置：直接放弃不建；**别硬凑浅止损**——浅于 1×ATR 会被正常波动扫掉（XMR 08-15 教训的镜像）
- 崩盘币/闪崩币天然进黑名单，等它波动收敛（ATR% 回落）后再重新评估
