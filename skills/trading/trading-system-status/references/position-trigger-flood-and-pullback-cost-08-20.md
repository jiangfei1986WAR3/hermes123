# 持仓期监控刷屏 + 加速普涨日回踩代价（2026-08-20）

## 1. 持仓期监控 Cron 的 TRIGGER 刷屏限流（XLM 例）

现象：XLM 开仓后价格持续站触发价上方 → 冷却期(600s)过后 signal_monitor 每 10 分钟重复写 TRIGGER 事件 → 监控包装脚本 grep TRIGGER → no_agent Cron 非空 stdout → 与持仓变动/移保本通知挤 30s 窗口 → `delivery_error: iLink sendmessage rate limited`。

判定：**无害**——只丢重复通知，执行链不受影响（事件由事件处理 Cron 处理，"已有持仓不重复开仓"安全门照常拦截，持仓托管照常跑）。代价=挤占真实通知配额。

处置选项（勿反复推销停用，给用户选）：
1. 停用该币价格监控 Cron（**保留 plan 文件**——持仓托管由 trading-cron.sh→manage 独立链负责，不受影响）
2. 接受偶发丢通知，保持现状

与过期场景（08-16/08-19 EXPIRED 刷屏）同源：包装脚本 grep 到的任何重复性输出行都会经 no_agent Cron 推送，源头在 signal_monitor 的重复事件写入。

## 2. 加速普涨日的回踩计划代价（FARTCOIN/ASTER 例，单日观察非硬规则）

环境：2026-08-20 大盘加速普涨（BTC +11.5% / ETH +18.9% 单日），6 轮扫描。

观察：
- **回踩计划 ×2 全错过**：FARTCOIN（12:15 建回踩计划）4 小时涨 4% 直接路过收复位 0.1525；ASTER（13:40 建）涨 2.2% 飞过 TP1 0.666。均无回踩进区，had_pullback 顺序判定拦"直接路过"——**设计正确但错过**。
- **突破计划吃满**：XLM（18:11 建，1h RSI 76.4）触发 0.1782 → 开仓滑点仅 +0.04%（历史上最好一档）→ TP1 20:51 成交 +1.35U → 移保本 SL=入场价 → 剩余半仓零风险搏 TP2。
- 逆势空单（TUT）：大盘暴涨期被 market_filter 拦（保护生效，但也说明加速日别指望空单）。

结论（倾向，非硬规则）：连续多轮扫描显示大盘加速（BTC/ETH 持续新高+名单稳定）时，突破类计划的期望收益显著高于回踩类——强势币不回踩。ENA 模式本身不动摇（4h RSI 85+ 仍不追突破），但"突破后超买建回踩计划"在加速普涨日的错过概率高，可用突破计划+浅止损替代。系统规则零改动，仅作为下一轮扫描的选型倾向。
