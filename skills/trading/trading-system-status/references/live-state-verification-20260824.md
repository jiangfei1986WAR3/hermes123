# 实盘状态核对补充（2026-08-24）

## 最终证据优先级

任何“是否开仓/是否成交”的结论必须以交易所实时状态为最终证据：先查 `positions`，再按 symbol 查 `userTrades`，最后查 `get_open_algo_orders` 确认 SL/TP。不能仅凭旧 executor 日志、旧 state 或事件目录判断当前是否空仓。

## 失败后续重试

日志必须按时间筛选。旧的失败记录可能早于后续成功重试；出现“失败→后来可能成功”时，读取日志对应时间窗口和尾部，并用成交记录交叉验证。

## dry-run 边界

`signal_monitor --dry-run` 只能证明规则当前是否满足，不能证明 executor 已执行，也不能证明账户是否成交。dry-run 输出 ALERT 后仍必须查成交、持仓和 Algo 条件单。

## 状态报告硬结论

“当前空仓/已开仓/未成交”等硬结论至少需要两类实时证据支持；尚未交叉核验时必须明确说“尚未确认”。

## 本次案例

BTC 先有多轮旧日志 `名义价值偏差过大`，后于 07:34 成功成交。仅读旧失败日志会误判最终状态。真实证据链为：`BUY 0.002 BTC @ 77688.10`、持仓 `0.002`、三个 Algo 单 `NEW`。
