# 名义偏差门与 floor 截断冲突 — 08-24 方案A修复

**一句话**：BTC 高价+200U 名义下，`round_qty` 的 `math.floor` 截断损失 22% 超过旧偏差门 15% → 触发即被拦、永不成交。08-24 选方案A：门 15%→25%（binance_executor.py 412 行，唯一一处），floor 保留。

## 现象与证据
- 计划：BTCUSDT 突破77591做多，08-23 18:25 建（Web端用户自建），有效期 08-24 18:25
- 05:17 起每 10 分钟（冷却 600s）触发一轮，共 8+ 轮，每轮日志：`参数: 保证金=10U 杠杆=20x 数量=0.002` → `校验失败: 名义价值偏差过大: 期望≈200U 实际=155.2U`
- 空仓、余额 97.949 分毫未动 = 拦截干净，无部分成交
- 安全门工作正常（钱没乱动），但计划结构上开不了仓——"良性拦截"与"功能性死计划"的区分点

## 根因链
1. 376 行 `quantity = round_qty(symbol, (margin*leverage)/entry_price)` → 200/77591 = 0.002578
2. 151 行 `round_qty` = `math.floor(qty * 10**precision) / 10**precision` → 0.002（BTC 步长 0.001）
3. 412 行校验3：偏差 22.4% > 15% → REJECT
→ floor 先缩水 22%，门只容忍 15%，两逻辑自相矛盾

## BTC 死区数学
- 名义 = margin×leverage = 200U 固定；floor 最大损失 = 1 步长 = 0.001 BTC
- 价格 76.7k~85k：200/price ∈ [0.00235, 0.00261] → floor 0.002 → 偏差 15%~24% 全被旧门拦（死区）
- >85k 偏差自动 <15% 能过；66.6k 附近 0.003 整除偏差 0（08-03 空单正常开仓即此类）
- 其他币（默认 100U 名义 10x）：floor 最大偏差 ≈ price/100000（ETH 3000U → 3%），永远 <15%，无影响
- 只有"高单价 + 小名义"组合才触线；当前仅 BTC 特殊配置（btc_margin=10/btc_leverage=20）命中

## 代码事实（改 executor 前必读）
- `round_qty` 共 5 个调用点：376 开仓 / 571 TP1 挂单 / 695+699 移保本重挂（末 TP 吃舍入误差）/ 1089 CLI 手动
- 条件单 `_place_conditional_order`（249 行）**不带 reduceOnly**：hedge mode 下加 reduceOnly 报 -1106；靠 positionSide 锁方向；超量触发实测行为（XRP 08-08）= 按可平量成交=全平，不反向开仓
- `place_order` 普通单（241 行）带 reduceOnly=true，仅紧急平仓路径用
- Python 浮点 round 边界实测（round(x,3)）：0.0015→0.002、0.0025→0.003、0.0005→0.001（.5 边界一律向上，无银行家舍入异常）
- 校验清单（executor 下单前防线）：①方向矛盾 ②当前价vs入场价 10% ③名义偏差 **25%（08-24 改）** ④TP 方向 ⑤止损距离 20% ⑥入场偏差门（偏离>止损距离拒，防追高）⑦滑点校准等距平移
- 15m K线收盘时刻 = 每小时 :00/:15/:30/:45（CST/UTC 同刻，8h 是 15m 整数倍）；require_close 检查的是最近一根**已收盘**线，盘中冲过不算
